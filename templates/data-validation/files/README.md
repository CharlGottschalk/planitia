# {{name}}

An MCP server (stdio) that validates JSON payloads. Generated by planitia from the
`data-validation` template.

## Setup

```sh
npm install
npm run build
npm test        # smoke test: starts the server, lists tools, calls them
```

Edit `src/schema.ts` to change what `validate` checks, then rebuild.

## Tools

Both tools are read-only (`readOnlyHint: true`, `destructiveHint: false`) and return
`{ "valid": boolean, "errors": [{ "path": "/json/pointer", "message": "..." }] }`.

### `validate`

Checks a payload against the zod schema in `src/schema.ts`.

| Input | Type | Description |
|-------|------|-------------|
| `payload` | any JSON value | The value to validate |

### `validate_json_schema`

Checks a payload against a JSON Schema (draft-07) sent with the call.

| Input | Type | Description |
|-------|------|-------------|
| `schema` | object | A JSON Schema |
| `payload` | any JSON value | The value to validate |

An invalid schema returns an `INVALID_SCHEMA:` error result.

## Guardrails

- **Input validation:** every tool's inputs are checked with zod before it runs. Bad input
  returns an error result (`isError: true`), and the server keeps running.
- **Errors:** failures come back as error results with a code prefix: `TIMEOUT`,
  `RATE_LIMITED`, `INVALID_SCHEMA` or `TOOL_ERROR`.
- **Logging:** JSON lines on stderr only. stdout carries the MCP protocol.
- **Timeout:** each call is limited to `TOOL_TIMEOUT_MS` (default {{timeoutMs}} ms).
  Validation is synchronous, so a pathological schema (e.g. a catastrophic regex `pattern`)
  can still block the server until it finishes. Only accept schemas from clients you trust.
- **Rate limit:** at most `RATE_LIMIT_PER_MINUTE` calls per minute across all tools
  (default {{rateLimitPerMinute}}; 0 = off).
- **Cache:** read-only results are cached in memory for `CACHE_TTL_SECONDS`
  (default {{cacheTtlSeconds}}; 0 = off).
- **No secrets:** this server needs no credentials.

## Configuration

| Env var | Default | Meaning |
|---------|---------|---------|
| `TOOL_TIMEOUT_MS` | {{timeoutMs}} | Per-call timeout |
| `RATE_LIMIT_PER_MINUTE` | {{rateLimitPerMinute}} | Max calls per minute, 0 = off |
| `CACHE_TTL_SECONDS` | {{cacheTtlSeconds}} | Result cache lifetime, 0 = off |

## Register with an MCP client

Build first, then use the absolute path to `dist/src/index.js`.

**Claude Code**

```sh
claude mcp add {{name}} -- node "$(pwd)/dist/src/index.js"
claude mcp list   # should show {{name}} as connected
```

Add `--scope project` to share the entry through `.mcp.json` (Claude Code asks you to approve it
on the next start), or `-e KEY=value` to set env vars.

**Codex**

```sh
codex mcp add {{name}} -- node "$(pwd)/dist/src/index.js"
```

Or add this to `~/.codex/config.toml`:

```toml
[mcp_servers.{{name|json}}]
command = "node"
args = ["/absolute/path/to/{{name}}/dist/src/index.js"]
```

**Cursor**

Add this to `.cursor/mcp.json` (project) or `~/.cursor/mcp.json` (global):

```json
{
  "mcpServers": {
    {{name|json}}: {
      "command": "node",
      "args": ["/absolute/path/to/{{name}}/dist/src/index.js"]
    }
  }
}
```
